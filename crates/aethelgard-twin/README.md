# aethelgard-twin

Simulator platform descriptions, the analog model, and the lock-step bridge for the Aethelgard digital twin (`docs/architecture.md` §3). Its register facts come from `aethelgard-svd-hal`. Each SPI controller it adds carries its receive DMA request line, numbered by RM0433 Rev 9 Table 124 as transcribed, with the citation, in `data/dmamux1-spi-rx.tsv` (`AET-WO-4400c2`); SPI6's request is on DMAMUX2, which Renode 1.17.0 does not declare, and its entry says so. On a foreign board, each declared serial port's USART carries its receive DMA request the same way, from `data/dmamux1-usart-rx.tsv` (`AET-WO-4400i` D2). For a foreign run with a declared input, `mavlink` holds the closed MAVLink 2 table (`data/mavlink-messages.tsv`, cited to ArduPilot's own message definitions), the input's refusals and the witness read from the firmware's transmission; `rest` the board at rest, from each IMU's declared orientation and each barometer's datasheet noise (`data/rest.tsv`).

Most devices are Renode 1.17.0's own models. The ICM-42688-P and the BMP581 are this project's (`models/renode/`, the `aethelgard-renode-models` crate, `AET-WO-4220`). `model::OWN` pins each by sha256, and the emitted platform's header names each one it declares with that pin. The CLI includes only a copy that hashes to it, and `platform::own_models` refuses any other (`ModelUnpinned`).

A generated platform replaces the stock `pwr` stub's script with one written from RM0433 Rev 9 §6.8 (`platform::pwr_override`, `AET-WO-4240v` D-3 (a)): `PWR_CR3` reads revision V's power-on `0x46` until its first write, which it stores, and `PWR_D3CR` stores `VOS`. `serial::judge_pwr` holds the logged PWR writes to the declared supply and VOS Scale 2 from `aethelgard_ir::vos`'s words. A foreign platform keeps the stock stub. What the twin cannot show of the sequence is `serial::PWR_RESIDUAL`.
