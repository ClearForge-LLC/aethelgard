## 2. The six critiques

### 2.1 Schema churn: agreed, and it has accelerated since the review

Since the review the version went 22 → 26. Version 27 is in flight (`1218`).
- **What each bump carried:** each of the four added keys or refusals: 23 the crystal generated (`4240b`), 24 pin-device validation (`1211e`), 25 the power sequence (`1216b`), 26 the IR pin-device backlog (`1217`). 27 admits test points beside pin devices (`1218`).
- **Why the cost is real:** every bump also costs a serial bench-package dispatch, about 25 minutes, before the next bump can land.
- **What has eased it:** `1215`'s refusal makes an old file's repair a list rather than a hunt.
- **What remains:** the epoch, at the P4 baseline.

### 2.2 The twin-to-silicon gap: agreed

See §1 item 3 for the ledger. The `1216` spike (#317) and `4300h` (#322) are examples of the gap being mechanized at the input side: a rule judges what silicon tolerates from a held page, and "not stated" is named, never passed.

### 2.3 Process overhead: half right, but the diagnosis is off

- **The process paid for itself this week.** Adversarial passes caught:
  - a 6.3 V pull onto a pin rated for 6 V at most (`1211d`);
  - a test-point reference collision that no board could escape (`1218`);
  - two of my own work-order errors, a wrong VDD bound and a wrong datasheet table (`1211e`).
- **The measured throughput limits are elsewhere:**
  - the serial bench-package queue: each specification bump forces a dispatch, a commit and a second CI run, about 50 minutes per work order;
  - the architect loop.
  
  Builder ceremony is not the bottleneck: overnight on 2026-11-22, five work orders merged with every gate (`1320`, `1216b`, `2308`, `1217`, `1321`).
- **Where I would look instead:**
  - decouple the bench package's sha lines from the specification version;
  - batch small rules into one work order (`1214`, `1217` and `1218` each did several);
  - fewer docs PRs.

### 2.4 Generated proof size: true, low priority

The proofs are generated and measured in every work order (`1211b`'s slowest harness took 48 s). The README statement is a small item for the next work order that touches `svd-hal`'s output.

### 2.5 Generality versus depth: right risk, wrong timing for a seam

Designing a second-vendor abstraction with no second real chip in hand is speculative. Instead, an **audit**: list every STM32-specific name in the IR (alternate-function numbers, register names, pin structures such as `1217`'s `io.analog_pads`) and quantify the coupling, with no abstraction built. The RP2350 stays the planned second target (`RUL-08`), after Sentinel-01's scar.

### 2.6 SI/PI/EMC/tolerance: agreed, taken now

P4's exit gate now names them as not covered, so "the pair survived simulation" cannot be read as covering them. See the roadmap amendment of 2026-11-22.

## 3. The Tviburi note (`2026-11-21-grok-tviburi.md`)

The gap ledger works only if Aethelgard's gates never take their verdict from Tviburi's own output (`INV-07`). Recording the hash of the ledger the twin emits, as Grok proposes, is the right seam: Aethelgard cites it and does not trust it.

The first Tviburi work order (`TVI-WO-0100`) has since been built twice, by Grok's team (Tviburi PR #2) and by a blind Claude builder. Both were judged blind against a fixed rubric. The comparison is recorded in the Tviburi repository, `docs/reviews/`.
