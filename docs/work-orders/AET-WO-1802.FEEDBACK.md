- **F5 · The engine image cannot know its commit · Q3 ruled backlog, then superseded by (B).** The image now states the commit its revision label names, and CI checks that the two agree.
- **F6 · My miss: the build-script rule, found by tier 1, not by me · stop, ruled (B) 22:29Z.**
  - `workspace_shape.rs` `no_member_has_a_build_script` has held since AET-WO-0100, whose §7 made "a `build.rs` that executes anything" a flag-and-stop. architecture §2 records why: a sandboxed `build.rs` on Furnace reached the D-Bus session and tmux's socket.
  - I built on a build script without checking for a rule against one. The adversarial pass, the architect's review and I all missed it. The full tier 1 caught it before any build script reached `main`.
  - **(A) declined:** a single build script allowed by sha256 pin. Reason: a build script that runs `git` would run on every machine that runs `cargo install aethelgard-cli`, and a `--version` nicety is not worth reopening that hazard.
  - **What (B) gives up:**
    - a crates.io or source build names no commit, and says so;
    - nothing in the binary can know clean or dirty;
    - a stated commit is the builder's claim, never proven from bytes.
  - **Why that is small:** a published version is an immutable snapshot and names its one source; the image's label and digest name its commit; and `-dev` already stops a build from `main` claiming a release.
