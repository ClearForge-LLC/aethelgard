# AET-WO-1800 — Every crate packages, so the first crates.io publish cannot fail halfway

**Repo:** `ClearForge-LLC/aethelgard` · **Base:** `main`, named in the kickoff.
**Branch:** `wo/aet-1800-publish-ready`.
**Author:** Claude (architect) · **Builder:** a cheap builder with a targeted adversarial pass (`docs/roadmap.md` §6). A fresh session on Furnace.
**Phase:** P1. It prepares the second half of the launch-readiness clause: "The same binary installs from crates.io under its published name." The publish itself is Scotty's, with his token, from his machine (`roadmap.md` §3). This work order makes that publish one ordered list of commands that is already proven to package.

**Grounds:**
- **crates.io refuses a crate whose path dependencies carry no `version`.** It also publishes exactly what `cargo package` puts in the `.crate`, so a vendored file left out of the package breaks the published build.
- **Every crate embeds data with `include_bytes!` or `include_str!` from its own `data/`:**
  - `aethelgard-svd-hal` embeds ST's header and pin XML;
  - `aethelgard-kicad-lib` embeds KiCad's files.

  Their licence and notice files must ship inside the package.
- **RFC 3463** removes crates that exist only to hold a name. `aethelgard-evolve` is a re-export stub today, so it is not published.
- **The CLI keeps its package name, `aethelgard-cli`,** and its binary stays `aethelgard`. `cargo install aethelgard-cli` installs `aethelgard` (architect's ruling, to avoid renaming every `-p aethelgard-cli` in CI, the images and the docs). No crate is published under the bare name `aethelgard` until one has real content.

> **What this is:** manifest metadata, licence files inside each package, and a CI step that packages every publishable crate in dependency order and builds the CLI from those packages.
>
> It is NOT:
> - a publish or a token;
> - a release workflow or trusted publishing (they follow the first manual publish);
> - a version bump (it stays `0.1.0`);
> - a code change.

**Cadence:** build-only. Stop only on §7. One PR, left unmerged.

## 1. Scope

1. **Manifests.**
   - Every `[workspace.dependencies]` path entry gains `version = "0.1.0"`.
   - Every member gains `readme`, `keywords` (at most 5), `categories` (valid crates.io slugs only), and `documentation` if it applies.
   - `aethelgard-evolve` gains `publish = false`.
   - `boards/sentinel-01` and its firmware keep, or gain, `publish = false`.
   - Path dev-dependencies stay path-only. Cargo strips them when it packages.
2. **Licence files in each package.**
   - Every published crate's `.crate` contains `LICENSE-MIT` and `LICENSE-APACHE`. Copy them into the crate directory, or name them with `include`.
   - `aethelgard-kicad-lib`'s package contains KiCad's `LICENSE.md`.
   - `aethelgard-svd-hal`'s package contains ST's `LICENSE.md`, `LICENSE` and both `SOURCE.md` files.
   - The root copies stay the canonical ones. A test asserts that each crate's copy is byte-identical to the root's.
3. **The publish order, proven.** A `gates` step runs `cargo package --workspace --locked` with the members in dependency order, or the equivalent per-crate loop. It then lists each `.crate` and asserts four things:
   - the licence and notice files above are present;
   - every `include_bytes!` and `include_str!` target is present;
   - no `target/`, `.git` or `boards/` path is present;
   - each `.crate` is under 10 MiB, the crates.io limit.

   The step then builds `aethelgard-cli` from the packaged sources, by `cargo package`'s own verification or a `cargo install --path` of the unpacked package, offline.
4. **`docs/releasing.md`** (new): the exact first-publish commands for Scotty, in order, each `cargo publish -p <crate>`. It says:
   - which machine to run them on, and what to check before each;
   - how to undo a mistake (`cargo yank`);
   - the one-time crates.io trusted-publishing setup that follows, for a later release workflow.

   It holds no token, and it never asks for one in a file or an argument.

## 5. Adversarial pass — targeted

1. Remove one vendored data file from a package, through `exclude`. The packaging step must fail, naming the file.
2. Drop a `version` from one path dependency. The step must fail.
3. Find any file that a published crate reads at build or run time from outside its own package directory.

## 5a. Reduction pass — diff-sized

One line in FEEDBACK's gates.

## 7. Flag-and-stop conditions

- A `.rs` change seems needed: for example, a path that reaches outside the crate. Report it; do not fix it.
- A crate is over 10 MiB.
- A test that can only go green by being weakened.
