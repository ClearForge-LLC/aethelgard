## Brown-out level

The specification declares brown-out reset level 3 (`mcu.bor_level`). A
part leaves the factory at level 0 (RM0433 Rev 9 Table 21, p. 177), and the
firmware reads the level but never programs option bytes, so each part is
programmed once, before the board is used, and read back:

1. Read `FLASH_OPTSR_CUR` (0x5200201C; RM0433 Rev 9 §4.9.8, p. 212).
2. Write 0x08192A3B, then 0x4C5D6E7F, to `FLASH_OPTKEYR` (0x52002008) to
   unlock `FLASH_OPTCR` (§4.5.1, p. 182).
3. Write to `FLASH_OPTSR_PRG` (0x52002020) the word read in step 1 with
   bits 3:2 (`BOR_LEV`) set to `11` and every other bit as read: the
   reserved bits must keep their reset value, and `RDP` (bits 15:8) must
   stay 0xAA, since any other value raises the readout protection level
   (§4.9.9, pp. 215-216). Read-modify-write of the word as read is the only
   procedure: no fixed word is right for every part. Three values are on
   record, each with `BOR_LEV` 00, and they agree only in bits 15:0:
   - 0x1BC6AAF0, read on the bench (AET-WO-3302, NUCLEO-H753ZI rev V,
     2026-11-16 05:00 UTC), for which the word to write is 0x1BC6AAFC;
   - 0x0006AAF0, RM0433 Rev 9 Table 21 (p. 177), the factory word
     with its part-dependent bits 28:27 and 20:19 at 0;
   - 0x0406AAF0, the twin's model (Renode 1.17.0).
4. Set `OPTSTART` (`FLASH_OPTCR`, 0x52002018, bit 1), wait until `OPT_BUSY`
   (`FLASH_OPTSR_CUR` bit 0) reads 0 (§4.4.3, p. 175), then set `OPTLOCK`
   (`FLASH_OPTCR` bit 0).
5. Read `FLASH_OPTSR_CUR` again: bits 3:2 must read `11`. The firmware's
   boot record then holds the same word, and a level other than 3 is
   `BrownOutLevelNotProgrammed`.

No programmer's command is given: ST's STM32CubeProgrammer user manual
(UM2237), which would state its option-byte syntax, is not held, and none
is cited here.
