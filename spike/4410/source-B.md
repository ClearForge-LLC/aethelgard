# research-B: writers of SYSCFG->PMCR in ArduPilot Copter-4.7.2 + ChibiOS (AET-WO-4410)
Tree: the pinned tree (fb773567, ChibiOS d103983f) (AP = that root). Repo = this repository.

## 1. Writers and readers (whole tree)
Searched (case-insensitive, whole tree incl. modules/): PMCR, PC2SO, PC3SO, PA0SO, PA1SO, BOOSTE, EPIS_, analog switch, SYSCFG; `->PMCR`, `PMCR =`, `PMCR |=`. Excluded only vendor register-definition headers under modules/ChibiOS/os/common/ext (definitions, not writers).

ONE writer in the entire tree, ChibiOS MACv2 (Ethernet):
- AP/modules/ChibiOS/os/hal/ports/STM32/LLD/MACv2/hal_mac_lld.c:305 `#if defined(STM32H7XX)`
- :306 `SYSCFG->PMCR |= SYSCFG_PMCR_PA1SO;`  (read-modify-write, sets bit 25 PA1 switch open; PA1 is ETH REF_CLK)
- :307 `#if defined(BOARD_PHY_RMII)`
- :308 `SYSCFG->PMCR = (SYSCFG->PMCR & ~SYSCFG_PMCR_EPIS_SEL_Msk) | SYSCFG_PMCR_EPIS_SEL_2;`  (EPIS_SEL = 0b100 RMII)
- :310 `SYSCFG->PMCR &= ~SYSCFG_PMCR_EPIS_SEL_Msk;`  (#else, MII)
- All three sit inside `bool mac_lld_init(void)` (:279), whole file under `#if HAL_USE_MAC || defined(__DOXYGEN__)` (:29).
- Every write is a masked RMW touching only bit 25 and bits 23:21. None references PC2SO (bit 26) or PC3SO (bit 27); neither is cleared or set. The RMW preserves reset state of PC2SO/PC3SO.
- Reached only if mac_lld_init runs: hal.c:101-105 `#ifndef _ARDUPILOT_ / #if (HAL_USE_MAC == TRUE) macInit(); ` is compiled OUT in ArduPilot (`-D_ARDUPILOT_` at AP/libraries/AP_HAL_ChibiOS/hwdef/common/chibios_common.mk:135). ArduPilot instead calls it at AP/libraries/AP_Networking/AP_Networking_ChibiOS.cpp:119 `if (!macInit()) {`.
- Macro control: HAL_USE_MAC defaults `#define HAL_USE_MAC FALSE` (AP/libraries/AP_HAL_ChibiOS/hwdef/common/halconf.h:125); chibios_hwdef.py:953-954 writes `#define HAL_USE_MAC TRUE` into hwdef.h only when `'ETH1' in self.bytype` (:952). BOARD_PHY_RMII comes from a hwdef.dat `define BOARD_PHY_RMII` line (e.g. ARKV6X/hwdef.dat:108, Pixhawk6X/hwdef.dat:101); the generator copies every `define X` line verbatim: chibios_hwdef.py:1007-1010 `if d.startswith('define '): ... f.write('#define %s\n' % d[7:])`. So HAL_USE_MAC and BOARD_PHY_RMII are plain `#define`s in generated hwdef.h, but they only select whether PA1SO/EPIS_SEL are written, never PC2SO/PC3SO.

Other places that touch SYSCFG on H7 (none touch PMCR):
- hal_lld.c:121 `SYSCFG->PWRCR = STM32_ODEN;` (PWRCR, not PMCR; under `#if defined(HAL_LLD_TYPE1_H)` and `!STM32_ENFORCE_H7_REV_XY`)
- hal_lld.c:177-185 reset of AHB4/APB4 peripherals deliberately skips SYSCFG: `__rccResetAHB4(~(RCC_APB4RSTR_SYSCFGRST | STM32_GPIO_EN_MASK));` ... `__rccResetAPB4(~RCC_APB4RSTR_SYSCFGRST);` (SYSCFG not reset; PMCR keeps its power-on value)
- hal_lld.c:248 `rccEnableAPB4(RCC_APB4ENR_SYSCFGEN, true);` (clock enable only)
- AP/modules/ChibiOS/os/hal/ports/STM32/LLD/GPIOv3/hal_pal_lld.c:181 `SYSCFG->EXTICR[cridx] = ...` (EXTI routing, not PMCR)
- GREP of `SYSCFG` in AP/libraries (all of ArduPilot's own code, .c/.cpp/.h/.py/.mk/.dat): zero hits. `PMCR` in AP/libraries and AP/Tools: zero hits. board.c, stm32_util.c, stm32_util.h, AnalogIn.cpp: no match for SYSCFG|PMCR|BOOSTE|PWRCR (they only #include stm32_util.h at board.c:20, AnalogIn.cpp:31).
- No generated hwdef.h macro of any name feeds PMCR: grep PMCR|PC2SO|PC3SO|BOOST in chibios_hwdef.py, hwdef.py, STM32H7*.py: NOT FOUND. Generator has no analog-switch or `_C` pad handling: grep `_C\b|PC2_C|PC3_C|PA0_C|PA1_C` in libraries/AP_HAL_ChibiOS/hwdef/scripts and libraries/AP_HAL/hwdef/scripts: NOT FOUND.

## 3. Conclusion
- (a) hwdef.h macro witness: PARTIAL AND ONLY INDIRECT. No macro carries PC2SO/PC3SO or the PMCR value. The only writer's value is not a macro; the macros that gate it (`HAL_USE_MAC`, `BOARD_PHY_RMII`) can be read by the existing `Preprocessed::value()` with no new parser (value("HAL_USE_MAC"), value("BOARD_PHY_RMII")), but they say whether the one known writer is compiled in, which writer provably never sets bits 26/27 (RMW with masks on bit 25 and 23:21: hal_mac_lld.c:306-310). So they are not a witness for PC2SO/PC3SO.
- (b) code immediates: The writer's operands (SYSCFG_PMCR_PA1SO, EPIS_SEL_2) are compile-time constants in instructions of mac_lld_init. Not data; check pinout does not decode code. Any other PMCR write (a raw-address store, a different firmware) would be code too, so invisible.
- (c) no unseen writer in source: true for the tree searched (single writer, bit 25 and 23:21 only), but "absence of writers in source" is not something check pinout reads. Neither the ELF reader (gpio_default_config and the tables above) nor header.rs/identity.rs has any witness for PMCR content. No ELF data symbol holds a PMCR image (no table or PMCR init constant exists in ChibiOS/ArduPilot for H7; hal_lld.c touches only PWRCR).
- Per the work order ("Judge PC2SO/PC3SO only from a witness check pinout already reads ... If none: stop with the source lines; do not invent one") the answer is: NO existing witness. Source lines to cite on stopping: hal_mac_lld.c:306-310 (sole writer, does not touch bits 26/27), hal_lld.c:177-185,248 (SYSCFG clock only, never reset so PMCR keeps reset value), hal.c:101-105 + chibios_common.mk:135 (macInit compiled out, called from AP_Networking_ChibiOS.cpp:119), chibios_hwdef.py:952-954,1007-1010 (hwdef.h gets HAL_USE_MAC/BOARD_PHY_RMII only by `define`), and the repo-side absence in elf.rs/header.rs/identity.rs.
- Possible (not-invented, flagged for architect) lever: a board that sets ETH1 + `define BOARD_PHY_RMII` is the only configuration where ArduPilot compiles any PMCR write, and the generic header reader could refuse/record HAL_USE_MAC. That is an extra witness for "the one known writer is in or out", not for PC2SO/PC3SO. Using it is a ruling, not an inference.
- Gap: raw-address writes (0x5800_0404) and Lua/runtime memory pokes were not searched for by address; MCU-variant check of the pinned H753 build path for `STM32H7XX` define was not verified (hal_mac_lld.c:305 `#if defined(STM32H7XX)`).
