# AET-WO-4240 source read: RM0433 Rev 9 and DS12117 Rev 10

Method: PyMuPDF text dump of the two local PDFs (scratch under /home/forge/.cache/aet-4240/pg/), plus rendered page images wherever table cells were missing from the text layer (Table 17, 57, 60, 33, 31, 36, 39, 40, 111, 133, 136, 137, all read from images). Page = the footer number printed on the page; in both PDFs it equals the PDF page index. The RM0433 footer reads "NNN/3329" (the WO's "/3353" does not match this PDF); DS12117 reads "NNN/357". Quotes are verbatim, shortened with "...". [inferred] marks my inference, not the document's words. Reset values are the register headers' "Reset value".

DS12117 is split by silicon revision: Section 6 (Tables 13 to 47ish, header "Electrical characteristics (rev Y)") and Section 7 (Tables 108 to 18x, header "(rev V)"). Where the two differ, both are given.

## Doubts and discrepancies

1. VCO max for the wide range differs between the two documents and between DS revisions: RM0433 p.402/404 and DS12117 rev V Table 136 say 960 MHz; DS12117 rev Y Table 39 says 836 MHz. The WO's "836" is the rev Y datasheet figure. Which silicon the bench board carries decides which number binds.
2. Wide-range PLL input: RM0433 says PLL ref is 1 to 16 MHz overall and the VCOL (medium) range is for <= 2 MHz refs; DS12117 Table 39/136 says the wide VCO needs 2 to 16 MHz input and Table 40/137 says the medium VCO needs 1 to 2 MHz. A 1 MHz ref therefore forces VCOSEL=1 (150 to 420 MHz) under the DS even though the RM's PLL1RGE field (00 = 1 to 2 MHz) does not say so.
3. DIVP1 parity: RM8.5.5 p.348 says "DIVP bitfield can only take odd values" (the field value) while the register description p.404 says "odd division factors are not allowed". These agree (value odd = even divisor, factor = value + 1), but value 0 (divide by 1) is also listed as valid in the register table, so the "only odd values" statement is loose. DIVR1 value 0 is "Not allowed". Mixing "value" and "factor" in the WO is a trap.
4. Rev Y vs rev V register differences visible in this RM: RCC_ICSCR (8.7.3, p.387, "available only on revision Y devices", reset 0x4000 0xxx) versus RCC_HSICFGR (8.7.4, p.388, "available only on revision V devices") and RCC_CSICFGR (8.7.6, p.390, revision V). Both sit near offset 0x004. adc_sclk "only available on revision V devices" (p.364).
5. The RM0433 Rev 9 text has no per-VOS sys_ck/CPU/hclk/pclk table. The only per-VOS system limits are in DS12117 Table 111 (rev V only). DS12117 rev Y Table 13 has no frequency or VCORE rows at all; rev Y limits come only indirectly (Table 39 note 2, consumption test conditions p.115, Table 2 note on p.21). Treat "rev Y: 400 / 300 / 200 MHz for VOS1/2/3, no VOS0" as [inferred] from those places.
6. DS12117 Table 2 says 480 MHz needs rev V; RM0433 Figure 49 (p.351) says "480 MHz Max" for the CPU branch without any revision tag. DS Table 111 footnote 5 ties 480 MHz and 240 MHz (hclk) and 120 MHz (pclk) to "TJMax = 105 °C"; Table 112 repeats 105 C for VOS0 only.
7. RM0433 flash Table 17 has a VOS0 column row 4 WS only at 225 to 240 MHz and a "-" for VOS1 4 WS; VOS2 4 WS is the single value "225 MHz". The table is by AXI interface clock, and its footnote defers to "the RCC section for the maximum product FACLK frequency", which the RCC section does not tabulate (Figure 49 only shows 240 MHz Max).
8. Table 57 in the PDF lists TIMPRE = 0 rows only. The TIMPRE = 1 behaviour is stated only in the RCC_CFGR bit text (p.392). With D2PPRE = /2 and TIMPRE = 0 the timer clock is hclk1 (not 2 x pclk) as the table's row "100 -> Frcc_hclk1" shows; with TIMPRE = 1 the same setting also gives hclk1 [inferred from the bit text].
9. RCC_CFGR MCO1 selects pll1_q_ck, MCO2 selects pll1_p_ck. The bit map label on p.391 reads "MCO11PRE" (typo for MCO1PRE); the field text on p.392 is correct.
10. CSS on HSE failure: the RM says the system switches to HSI ("automatically switches to the HSI"), RCC_CR HSION is HW-set, SW is HW-forced to HSI (p.393). STOPWUCK is called the "emergency clock for the Clock Security System on HSE" (p.393), which could make it CSI when STOPWUCK=1; the 8.5.3 text does not say so.
11. DS12117 Table 33 has no drive-level, ESR or load-capacitance rows (NOT FOUND); only Gmcritmax 1.5 mA/V, tSU typ 2 ms (no max given), RF 200 kOhm, IDD. Table 31 has no rise/fall or duty-cycle row (NOT FOUND).
12. The WO's "/3353" footer style does not match: this RM0433 PDF is "/3329" (3329 pages).
13. Not read in full: rev Y Table 40 jitter cells (p.131), rev V HSE oscillator figure, HSI48 tables. Marked above where relevant.
14. RM0433 6.4.1 text (p.262) says the system waits on ACTVOSRDY (PWR_CSR1) before changing VOS, while the VOS0 sequence (p.280) says wait on VOSRDY; they are different bits (PWR_CSR1 bit 13 vs PWR_D3CR bit 13).
